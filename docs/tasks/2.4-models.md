# Task 2.4 — SQLAlchemy models

## Objective

The base every table inherits: a constraint naming convention Alembic can work
with, a UUID primary key, and timestamps.

## Context

Domain tables belong to the phases that need them — users in 3.1, organisations in
4.1, documents in 5.4. Inventing them now would be speculative. What cannot wait is
the naming convention: without one, Postgres names constraints itself in a form the
metadata cannot predict, and a later migration has nothing to drop them by.

## Implementation steps

1. `models/base.py` — `Base` with a `MetaData` naming convention, `UUIDPrimaryKey`,
   `Timestamps`.
2. Re-export from `models/__init__.py`, with the rule that every model must be
   imported there or Alembic will generate a migration dropping its table.
3. Tests: constraints are named, the id is application-supplied with no server
   default, timestamps are set by the database and timezone-aware.

**Excluded:** every domain table.

## Acceptance criteria

- `pk_`, `uq_`, `fk_`, `ix_`, `ck_` constraints all carry predictable names.
- The primary key is a UUID the application supplies; no server-side function.
- `created_at`/`updated_at` are timezone-aware and set by the database.
- `scripts/check.sh` passes, integration included.

## Tests

Unit for naming and column configuration; integration for the timestamps.

### Deviations
- **A claim in the first draft was wrong.** The docstring said the id is "known
  before the insert"; a SQLAlchemy column `default` runs at flush, not at
  construction. Caught by the test asserting it. Both the docstring and the test
  now describe what actually happens.
- **Dropped an assertion on `column.default.arg is uuid.uuid4`.** It failed with
  two different `uuid4` objects. Checked for a duplicate import path — there is
  none, `uuid` is a single module under pytest — so it is SQLAlchemy copying the
  shared `mapped_column` between subclasses. That is its internals, not this
  code's behaviour, and asserting it buys nothing.
- **Tables reached through `Base.metadata.tables[...]`** rather than `__table__`,
  which declarative types as `FromClause` — no `.constraints`, and not a `Table`.

- **The timestamp test was flaky and was fixed, not retried.** `created_at <=
  datetime.now(UTC)` compares the database's clock with this process's; they
  differed by 11 ms and the gate caught it. Now asserts the value is within a
  minute of now — still tight enough to catch an epoch date or a naive timestamp
  read as UTC, without depending on two clocks agreeing.

### Known limitations
- No domain model exists yet, so the base is exercised by a throwaway table.
- Soft deletes, optimistic locking and tenant scoping are not modelled; each
  belongs with the phase that needs it, and tenant scoping is 4.6.
