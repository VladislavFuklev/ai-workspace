# Task 0.4 — Code quality tooling

## Objective

One command per workspace that formats, lints and type-checks, with identical
results on a contributor's machine and in CI.

## Context

Task 0.2 left ESLint installed by the Next.js scaffolder but unconfigured beyond
its default, and the Python side has no linter, formatter or type checker at all.
Task 0.6 will run whatever this task defines, so the commands must be
non-interactive and exit non-zero on failure.

## Prerequisites

- Tasks 0.2 and 0.3 complete.

## Implementation steps

1. **Web** — add Prettier (with the Tailwind class-sorting plugin), reconcile it
   with the existing `eslint.config.mjs`, and add rules that enforce the layering
   in `docs/ARCHITECTURE.md` (no cross-feature internal imports, no import from
   `app/` into `features/`) using an import-boundary rule.
2. **API** — add Ruff (lint + format) and a type checker, configured in
   `apps/api/pyproject.toml`. Enable rule sets deliberately rather than everything;
   record which and why.
3. Decide the TypeScript version question deferred in 0.2: the scaffold pins `^5`
   while TypeScript 7 exists. Check whether `eslint-config-next` and the Next.js
   plugin support 7 before moving, and record the outcome.
4. Add root scripts so one command checks everything, and a `--fix`/`--write`
   variant that is never run implicitly by the check command.
5. Add `.editorconfig`.
6. Consider a pre-commit hook. Only if it stays fast; a slow hook gets bypassed.

## Acceptance criteria

- A single documented command reports lint, format and type status for both apps.
- Every check exits non-zero on a real violation, verified by introducing one.
- Formatting is deterministic: running the formatter twice changes nothing.
- The checks pass on the current codebase without weakening a rule to achieve it.
- No check requires network access.
- Layering rules actually fail on a deliberate cross-feature import.

## Tests

No unit tests. Verification is running each check against a deliberately broken
file and confirming the failure, then reverting.

## Documentation

Update `docs/ARCHITECTURE.md` (toolchain table), `docs/PROJECT_STATE.md`,
`docs/CHANGELOG.md`, `docs/ROADMAP.md`, this file, and `docs/DECISIONS.md` for the
TypeScript version decision and the Ruff rule-set choice.
