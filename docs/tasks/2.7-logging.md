# Task 2.7 — Structured logging

## Objective

Every log line a queryable record: JSON outside local, a request id on all of
them, and nothing sensitive on any of them.

## Context

2.6's readiness checks already log full exception detail deliberately kept out of
the response body. That only works if the logs go somewhere structured.

## Implementation steps

1. structlog: JSON outside local, console locally; the standard library routed
   through the same processors so third-party logs match.
2. A request-id context variable, so a line written deep in a repository carries
   it without threading a parameter.
3. Middleware assigning the id, logging every request's outcome and duration, and
   returning the id in a header.
4. Honour a valid inbound id so a trace spans services; replace anything else.
5. A redaction processor for credential-shaped keys.

## Acceptance criteria

- JSON outside local; human-readable locally.
- Every response carries `X-Request-ID`; two requests get different ids.
- A valid inbound id is honoured; a malformed one is replaced.
- A line written outside the request path still carries the id.
- Credential-shaped keys are redacted.
- `scripts/check.sh` passes.

## Tests

Unit, capturing the handler's own stream.

### Deviations
- **A real bug, visible only on a live request.** The success log line was written
  after the context variable was reset, so it went out with no `request_id` — the
  one thing the id exists for. Found by running the server and reading its output,
  not by a test. A test now covers it, and was confirmed to fail against the
  original code.
- **Double rendering.** With `LoggerFactory`, the last structlog processor must be
  `ProcessorFormatter.wrap_for_formatter`; rendering in both places produced JSON
  whose `event` was another JSON object.
- **Tests capture the handler's stream, not `capsys`.** A handler binds its stream
  when it is created, so `capsys` — which swaps `sys.stderr` afterwards — sees
  nothing. `create_app` also reconfigures logging, so the buffer must be attached
  after the app exists.

### Known limitations
- Redaction matches key names, not values. A token pasted into a free-text field
  is not caught; the defence is not logging such fields.
- No sampling or rate limiting on request logs. Fine at this volume; revisit at
  11.5.
