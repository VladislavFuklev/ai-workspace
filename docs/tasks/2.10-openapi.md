# Task 2.10 — OpenAPI documentation

## Objective

A schema good enough to generate a client from: readable stable operation ids,
the error envelope documented on every operation, and docs closed outside local.

## Context

ADR-005 makes the OpenAPI document the contract between the two apps — nothing is
shared at compile time. Task 1.7 already validates responses against it by hand;
a generated client is the natural next step (phase 12 or 14).

## Implementation steps

1. Operation ids from the route name via `generate_unique_id_function`, not
   FastAPI's path-derived default.
2. Refuse duplicate ids when the document is built.
3. `422` and `500` with the error envelope on every operation.
4. A description that explains the error contract and `X-Request-ID`.
5. Tags; `servers`; build the document once and cache it.

## Acceptance criteria

- No operation id contains the path or a doubled separator.
- A duplicate id is refused.
- Every operation documents 422 and 500 with `ErrorResponse`.
- `ErrorResponse` is in `components.schemas` with all four fields.
- `/docs` and `/openapi.json` answer locally and 404 in production.
- The document is built once.
- `scripts/check.sh` passes.

### Deviations
- **`generate_unique_id_function` rather than rewriting `app.routes`.** The first
  version walked the route table, which in FastAPI 0.141 does not contain the
  routes of included routers — the same discovery as 2.9. Duplicate detection
  moved to the built document, the only place every route is visible.

### Known limitations
- No security schemes; there is no authentication until phase 3.
- No generated TypeScript client yet. The schema is now good enough for one, and
  it would remove the hand-written response schemas in `apps/web/src/lib/api`.
- Examples are not specified per operation; worth adding once endpoints have
  interesting bodies.
