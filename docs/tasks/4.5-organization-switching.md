# Task 4.5 — Organization switching

## Objective

Give the web app a current organisation: pick one, see it in the shell, keep it
across reloads, and switch without losing where you are.

## Context

The API names the tenant in the path (`/api/v1/organizations/{slug}/...`), so
"current organisation" is a frontend concern. Two candidate homes for it:

- **The URL** — `/[locale]/[organization]/...`. Shareable, bookmarkable, and two
  tabs can show two organisations. Costs a route-group reshuffle.
- **A cookie** — cheap, but a link no longer identifies what it shows, and two
  tabs fight over one value.

Recommendation: the URL, with a cookie only as the memory of the last one used,
so `/[locale]` can redirect to somewhere sensible.

A user with no organisations must land somewhere that works — the API creates
none at registration.

## Implementation steps

1. Route segment `[organization]` under the app group; the layout resolves the
   slug and 404s on a slug the caller cannot see.
2. Server-side fetch of the caller's organisations for the switcher.
3. Switcher in the app shell: current one, the rest, and a create action.
4. Remember the last slug in a cookie; `/[locale]` redirects to it, else to the
   first organisation, else to an empty state that creates one.
5. Create form, reusing the existing form + error-message plumbing.
6. Messages in `en` and `uk`.

**Excluded:** role changes and member management over HTTP (4.6), the isolation
sweep (4.7), invitations (phase 10).

## Acceptance criteria

- A slug the caller does not belong to renders not-found, not an error page.
- Reload keeps the organisation; a second tab can show a different one.
- Switching from a page keeps the equivalent page in the new organisation.
- A user with no organisations is offered creation, not a broken shell.
- Both catalogues have the same keys; `scripts/check.sh` passes.

## Tests

Server-side helpers directly; the rest through markup and the generated CSS
until 12.1 brings a web test runner.

## Outcome — completed 2026-09-13

The organisation is in the URL: `/{locale}/{organization}/{section}`. `/enter`
decides which one when nobody has said, `/organizations` picks or creates one,
and a cookie remembers the last choice.

| --- | --- |
| signed out, any organisation URL | 307 to sign-in with `?next=` |
| signed in, no organisations, `/en/enter` | 307 to `/en/organizations`, which offers creation |

### Deviations
- **Reserved slugs are enforced by the API, not just avoided by the web app.**
  Putting the slug directly under the locale means an organisation called "Sign
  In" would be shadowed by a page. The API suffixes such a slug — the name is
  still accepted, only the address changes — and `scripts/check-reserved.mjs`
  fails if the API list, the web list and the actual route tree disagree.
- **`/{locale}/{organization}` redirects from the middleware, not from a page.**
  Written as a page it worked, but the layout above it had already begun
  streaming, so the redirect arrived after a shell the visitor never wanted. The
  middleware answers before anything renders.
- **The memory cookie is written by the middleware.** A Server Component cannot
  set one, and a server action for this would be a round trip to record
  something the middleware already sees.
- **`getServerUser` is wrapped in React `cache`.** The guard layout and the
  header below it both ask; `no-store` fetches are not deduplicated.
- **`AppHeader` lives beside the routes, not in `components/`.** It composes a
  feature (sign out) and the layering lint (ADR-012) rightly refuses that in the
  shared component layer.
- **`serverGet` replaced the hand-rolled fetch in `features/auth/server.ts`,**
  and returns a status rather than `null`, so a layout can tell "you may not see
  this" (not-found) from "the API is down" (error boundary).

### Known limitations
- The switcher menu is client-side, so its behaviour — opening, Escape, and
  keeping the section when switching — is verified by reading the code, not by a
  test. Browser automation is 12.8.
- The remembered slug is one per browser, not per tab. Two tabs on different
  organisations both work; whichever loaded last decides where `/enter` goes.
- No page under a section names the organisation yet; they are still the phase-1
  placeholders.
