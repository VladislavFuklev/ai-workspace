# Task 2.3 — Database connection

## Objective

One engine per process and one session per request, with a transaction boundary
that cannot leave a half-applied write behind.

## Context

2.1 left the lifespan empty for exactly this. The `backend-quality` skill fixes
the rule: the session is opened and closed by a dependency, the service layer
defines the transaction, and the repository never commits.

## Implementation steps

1. `core/database.py` — `create_engine`, `create_session_factory`, `session_scope`.
2. Open the engine in the lifespan, dispose it on shutdown.
3. `SessionDep` so handlers receive a session rather than building one.
4. Pool sizing as settings.
5. Integration tests against the real database, opt-in by marker, run by
   `scripts/check.sh` when the stack is up and *reported as skipped* when not.
6. A Postgres service in CI so the same tests run there.

## Acceptance criteria

- The engine connects and `pg_extension` shows `vector`.
- A session that raises rolls back; the write is gone.
- Sessions are closed after use.
- An unreachable database fails at connect with a SQLAlchemy error, not at import.
- CI runs the integration tests against a real Postgres.
- `scripts/check.sh` passes and says when integration was skipped.

### Deviations
- **Integration tests are opt-in by marker and excluded from the default run**, so
  a machine without the stack still gets a green unit run. `scripts/check.sh` runs
  them anyway and prints an explicit *skipped* line when it cannot — a suite that
  quietly runs nothing is worse than one that fails.
- **`expire_on_commit=False`.** Otherwise serialising a response after a commit
  triggers a lazy refresh on a closed session.
- **Committing is not `session_scope`'s job.** Only the caller knows where a unit
  of work ends; the scope guarantees rollback and close, nothing more.
- **Ruff's S608 fired on the rollback test's f-string SQL.** Rewritten with literal
  statements rather than ignored — the rule is worth keeping on in tests too.
- **`enable_pgvector.py` added for CI**, which has no init hook. 2.5 handles the
  extension in a migration for environments built from neither.

### Known limitations
- No models yet (2.4), so nothing uses `SessionDep`.
- Pool sizes are per process; the real ceiling is Postgres `max_connections`
  divided by the number of API processes. Revisit at 13.6.
