# Task 1.6 — Error, loading and empty states

## Objective

One implementation of each non-success state, so every surface built from phase 5
onwards gets the same behaviour instead of inventing it.

## Context

Task 1.1 shipped a route-level `error.tsx` and a hand-written skeleton; 1.4 left
four destinations with a bare heading. The `ui-review` skill treats loading, empty,
error and success as the bar for every data surface.

## Implementation steps

1. `Skeleton`/`SkeletonText`, `EmptyState`, `ErrorState`, `Spinner` under
   `components/ui/`, with a barrel export.
2. Recompose `error.tsx` and `(app)/loading.tsx` on them.
3. Give each destination a real empty state — what it is, why it is empty, and the
   action that fills it.
4. Accessibility: skeletons hidden from assistive technology, `role="alert"` on
   errors, `role="status"` plus a text label on the spinner.

## Acceptance criteria

- No surface renders a bare heading or a naked "No data".
- Error copy never contains raw error text; a digest is shown as a reference.
- Every state component uses tokens only.
- `scripts/check.sh` passes.

## Tests

Component tests are 12.2. Verification is the served markup: roles, `aria-busy`,
and the absence of raw error text.

### Deviations
- **`loading.tsx` moved from `(app)/workspace/` to `(app)/`** so every destination
  gets it rather than one route.
- **Empty-state actions render disabled**, labelled with the phase that enables
  them. A working-looking button that does nothing is worse than an honest one.
