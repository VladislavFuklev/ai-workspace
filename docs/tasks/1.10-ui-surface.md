# Task 1.10 — Reusable UI surface

## Objective

One place to see every shared component in the states it actually ships in, so a
regression in an empty or error state is visible instead of waiting for a user to
find it.

## Context

`(dev)` has held the token page since 0.8 and gained a form demo in 1.9. This
turns it into a navigable reference and adds the component states.

## Implementation steps

1. `(dev)/layout.tsx` gains a header, an "internal" marker, and navigation.
2. `(dev)/components` — every shared component, including the awkward cases.
3. Active state in the dev navigation, same mechanism as the product nav.

## Acceptance criteria

- Tokens, Components and Forms are reachable from each other with a correct
  active state.
- The gallery shows loading, empty (with and without an action) and error,
  including a long-content case.
- The surface is visibly marked as not part of the product.
- `scripts/check.sh` passes.

### Deviations
- **A page rather than Storybook.** Storybook is a second build, a second
  dependency tree and a second place for config to drift; the value here is seeing
  the states, which a route already gives — using the app's own build, tokens and
  theme.
- **The gallery leads with the awkward cases.** A gallery of happy paths is where
  empty states go to be forgotten.

### Known limitations
- `(dev)` is reachable in production builds. Gating needs a decision — an env
  flag, or excluding the group at build time — and belongs with deployment (13.2).
- No visual regression testing; 12.9 covers accessibility checks.
