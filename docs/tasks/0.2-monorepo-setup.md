# Task 0.2 — Monorepo setup

## Objective

Create the physical workspace structure decided in task 0.1, so that both apps can
be installed and run as empty-but-valid projects. No product features.

## Context

Task 0.1 fixed the topology and toolchain in `docs/ARCHITECTURE.md` and ADR-001
through ADR-005. This task materializes those directories and manifests.

## Prerequisites

- Task 0.1 complete.
- Local: Node 22 LTS, pnpm 11.x, uv, git.

## Implementation steps

1. Root JS workspace: `package.json` (private, `packageManager`, `engines`),
   `pnpm-workspace.yaml` covering `apps/*` and `packages/*`, `.nvmrc` with Node 22.
2. Create `apps/web` as a Next.js App Router + TypeScript + Tailwind project.
   Do not build any product UI — the default shell is enough.
3. Create `apps/api` as a uv project: `pyproject.toml`, `.python-version` (3.13),
   `src/ai_workspace_api/__init__.py`, and the layer directories from
   `docs/ARCHITECTURE.md` (`api`, `services`, `repositories`, `models`, `schemas`,
   `workers`, `ai`, `core`) with package markers only.
4. Add FastAPI and uvicorn as API dependencies; generate `uv.lock`.
   Do not implement the application structure — that is task 2.1.
5. Create `scripts/` with the minimum needed to install and run both apps.
6. Verify `.gitignore` covers the generated artifacts.

## Acceptance criteria

- `pnpm install` succeeds from the repository root.
- `uv sync` succeeds in `apps/api`.
- The web dev server starts and serves the default page.
- Directory layout matches `docs/ARCHITECTURE.md` exactly.
- No lockfile, `node_modules/` or `.venv/` is committed except `pnpm-lock.yaml`
  and `uv.lock`.
- No authentication, database, or AI code exists.

### Deviations from the plan, and why
1. **Empty web layer directories not created.** `src/features`, `src/components`,
   `src/lib`, `src/styles`, `tests`, `e2e` would have been empty placeholders that
   git cannot even track without `.gitkeep` filler. The layering contract is
   documented in `docs/ARCHITECTURE.md` and enforced in review; directories appear
   with their first real file. The API layer packages *were* created because
   `__init__.py` files are functional package markers, not filler.
2. **ESLint was installed even though `--eslint` was not passed.** The Next.js 16
   scaffolder includes it unconditionally. Left in place rather than ripped out and
   re-added; task 0.4 owns configuring it properly alongside Prettier, Ruff and
   mypy.
3. **`migrations/` not created.** Alembic generates its own layout in task 2.5.
4. **`typecheck` runs `next typegen` first.** Next.js 16 emits global route types
   (`LayoutProps`, `PageProps`) into `.next/types`; a bare `tsc --noEmit` fails on a
   clean checkout without them. Verified by deleting `.next/` and re-running.
