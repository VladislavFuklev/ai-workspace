# Task 1.1 — Next.js application shell

## Objective

The routing skeleton the product hangs from: route groups separating the public
surface from the authenticated one, a root layout that establishes theme and
metadata, and top-level error and not-found boundaries — so every later feature
lands in a defined place with defined failure behaviour.

## Context

`apps/web/src/app` is the scaffold's `page.tsx` plus `/design` from task 0.8.
Design tokens exist (0.8); nothing consumes them outside `/design`.

Next.js 16 differs from earlier versions in ways that matter here: `error.tsx`
receives **`retry`**, not `reset`, and `global-not-found.tsx` is a new convention
for unmatched routes. Read the bundled docs before writing any of them.

## Prerequisites

- Phase 0 complete.

## Implementation steps

1. Route groups: `(marketing)` for the public surface, `(app)` for the
   authenticated product. Groups do not appear in the URL.
2. Root layout: `<html>` with `lang`, the font variables, `suppressHydrationWarning`
   for the theme attribute, and a `viewport` export with `themeColor` for both
   colour schemes.
3. A shell frame in `(app)/layout.tsx`: a header region and a `<main>` with a skip
   link. Structure only — the responsive sidebar and breakpoints are task 1.2.
4. Boundaries: `error.tsx` (client, `retry`), `not-found.tsx`, `global-error.tsx`,
   and a shell-level `loading.tsx`.
5. Move `/design` under a group so it is not mistaken for a product route.
6. Placeholder `(app)/page.tsx` and `(marketing)/page.tsx` that use tokens rather
   than raw colours.

**Excluded:** responsive layout and breakpoints (1.2), navigation (1.4), theme
switching UI (1.5), reusable state components (1.6), API client (1.7).

## Acceptance criteria

- `/`, `/design` and an unmatched path all render; the unmatched path returns 404.
- `error.tsx` renders and its retry control works; verified by a route that throws.
- Every route uses semantic tokens; no raw colour or hex outside `globals.css`.
- A skip link is the first focusable element and moves focus to `<main>`.
- Exactly one `<h1>` per page; landmarks (`header`, `main`) present.
- `scripts/check.sh` passes; no horizontal overflow at 375px.

## Tests

No unit tests (component tooling is 12.2). Verification is rendering each route,
exercising the error boundary, and checking the served markup for landmarks and
heading structure.

### Deviations
- **`(marketing)` owns `/`, not `(app)`.** Both groups resolving to `/` is a build
  error, and 14.1 will want the landing page at the root. The product lives under
  concrete routes (`/workspace`), so the collision cannot happen later.
- **`LayoutProps<"/">` on every group layout**, including the one wrapping
  `/workspace`. Route groups create no URL segment, so Next generates
  `LayoutRoutes = "/"` only. Read from the generated `routes.d.ts` after
  `LayoutProps<"/workspace">` failed to compile; noted in the file so it is not
  "fixed" back.
- **`themeColor` duplicates `--color-bg`** — metadata cannot read CSS.
  `check-contrast.mjs` now asserts the two match, and was confirmed to fail when
  they do not.
- **The throwing route was deleted after verification.** It also revealed that a
  route which throws during prerender fails the build outright; `force-dynamic`
  was needed to test the runtime path.

- **`next typegen` does not prune stale route types.** After the throwing route
  was deleted, `tsc` still failed on a generated reference to it. Deleting
  `.next` fixes it. Local only — CI starts from a clean checkout.

### Known limitations
- The error boundary's rendered UI was confirmed only by its presence in the
  client chunk plus the 500 shell — React renders it after hydration, so curl
  cannot see it. Needs a browser, or Playwright at 12.8.
- No responsive frame, navigation or theme switcher yet (1.2, 1.4, 1.5).
- `(dev)` is reachable in production builds; gating is task 1.10.
