# Task 1.4 — Navigation

## Objective

Fill the navigation region 1.2 left empty: the product's top-level destinations,
with a correct active state, working in both the desktop sidebar and the mobile
drawer.

## Context

1.2 built the frame and noted two things to resolve here: the `<nav>` has no
content, and two `<nav aria-label="Main">` landmarks exist because the sidebar
renders twice.

Navigation needs destinations. The five top-level areas are already implied by the
roadmap — documents (phase 5), the assistant (phase 7), usage (phase 10), settings
(phase 4) — so this task creates route skeletons for them in the same placeholder
style as `/workspace`, not product behaviour.

## Implementation steps

1. A single source of truth for the items: href, label, icon.
2. Client nav component using `useSelectedLayoutSegment`, since only that segment
   decides which item is current. `aria-current="page"` on the active item, not
   colour alone.
3. Route skeletons for each destination under `(app)`.
4. Closing the drawer on navigation — otherwise it stays open over the new page.
5. Resolve the duplicate landmark: the drawer's `<nav>` drops its label, since the
   `<dialog aria-label="Navigation">` already names that region.
6. Focus-visible styling on every item, from the tokens.

**Excluded:** organisation switcher (4.5), user menu and theme toggle (1.5),
breadcrumbs, and anything the destinations will eventually contain.

## Acceptance criteria

- Every item navigates, and the matching item carries `aria-current="page"`.
- Exactly one `<nav>` is named in the accessibility tree at any breakpoint.
- The drawer closes when a link inside it is followed.
- Active state survives a direct page load, not only client navigation.
- Every item is keyboard reachable with a visible focus ring.
- `scripts/check.sh` passes; no raw colour or dimension.

## Tests

No component tests yet (12.2). Verification is the served markup for each route:
one `aria-current="page"`, correct landmark naming, and all items present.

### Deviations
- **`useSelectedLayoutSegment`, not `usePathname`.** Only the first segment under
  `(app)` decides the destination, so `/documents/abc` keeps Documents current
  with no prefix matching to get wrong later.
- **`Sidebar` deleted.** It was a placeholder for exactly this; `AppShell` now
  renders `Navigation` directly, which also removed the `id` prop and the
  `sidebar`/`drawerSidebar` pair 1.2 needed.
- **Route skeletons for four destinations.** Navigation to a 404 is not
  navigation. They follow the `/workspace` placeholder pattern and contain no
  product behaviour.

### Known limitations
- Icons are inline paths in `navigation-items.ts`. Fine at five; revisit if the
  set grows or a real icon library arrives.
- Drawer-closes-on-navigate is wired but, like the rest of the drawer, confirmed
  from the code path rather than observed — no browser automation until 12.8.
