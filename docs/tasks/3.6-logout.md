# Task 3.6 — Logout and session revocation

## Objective

End one session or all of them, and stop two browser tabs refreshing at once
from looking like a stolen token.

## Context

3.5 left two gaps. Nothing reads the access token yet, so there is no "who is
calling"; and rotation treats a concurrent refresh as a replay, which signs the
user out for having two tabs open.

## Implementation steps

1. An authentication dependency: access cookie → user and session, or 401. This
   is what every protected endpoint from phase 4 will use.
2. `POST /auth/logout` — revoke the current session and clear both cookies.
3. `POST /auth/logout-all` — revoke every session for the user.
4. `GET /auth/me` — who am I; the frontend needs it to decide what to render.
5. A short grace window on rotation: a token retired seconds ago, whose successor
   is still live, is a second tab rather than a thief.

## Acceptance criteria

- `me` returns the profile with a valid access cookie and 401 without one.
- An expired or tampered access token is 401.
- Logout revokes the session and clears both cookies, at their original paths.
- After logout the refresh token no longer works.
- Logout-all ends every session, including ones from other sign-ins.
- Two refreshes inside the grace window both succeed and neither revokes the
  family.
- A retired token replayed *after* the window still revokes the family.
- `scripts/check.sh` passes.

### Deviations
- **The principal dependency reads the user row.** ADR-019 says the access token
  is checked by signature alone, and it mostly is — but a disabled account has to
  stop working now rather than in fifteen minutes, and that costs one indexed
  read. Stated here because it is a deliberate departure from the ADR's spirit.
- **The grace window needs two conditions, not one.** Recently retired is not
  enough — a fast thief would qualify. The family must also still have a live
  session, which means the legitimate rotation is what retired it.
- **Adding the window silently weakened an existing test.** 3.5's replay test
  replayed immediately, which is now the benign path; only running the whole
  suite caught it. It now ages the token past the window, so it still asserts
  what it was written for.
- **The fixture factory produced untyped functions** that strict mypy rejected. A
  typed `Api` dataclass and two explicit fixtures replaced it — better than the
  `noqa` the first version reached for.

### Known limitations
- The grace window is also the window a thief has. Ten seconds is a guess;
  shortening it trades usability for a narrower gap.
- No device, IP or last-used recorded, so a future "your sessions" screen has
  nothing to show. Worth adding when that screen exists.
- Logout cannot invalidate an already-issued access token. That is ADR-019's
  stated cost, bounded by the fifteen-minute lifetime.
