# Task 1.7 — API client

## Objective

One way for the web app to reach the API: base URL, timeout, credentials, error
normalisation and response validation in a single place.

## Context

ADR-005 keeps the two dependency graphs independent, so nothing is shared at
compile time — the contract has to be *checked* at runtime, not asserted with a
cast. The API has no endpoints yet (2.1), so the transport is what ships here.

## Implementation steps

1. `createApiClient({ baseUrl })` — a factory, so the base URL is an argument and
   the module imports no configuration.
2. `ApiError` with a `kind` discriminator (network, timeout, http, parse) and a
   retryability rule.
3. Zod schema validation of every response body at the boundary.
4. A bounded timeout on every request, combinable with a caller's own signal.
5. The configured instance in `lib/api/index.ts`.

## Acceptance criteria

- A valid response parses to a typed value.
- A body that does not match its schema throws `kind: "parse"`, and the message
  carries no Zod detail.
- An HTTP failure keeps status, server code and request id, and 4xx is not
  retryable while 5xx is.
- A failure response with no JSON body still produces a useful error.
- A slow request aborts at the timeout and is classified as such.
- Query params serialise; `undefined` is dropped.

## Tests

No web test runner until 12.1. Verified against a stub HTTP server exercised
through a temporary Next route handler, which has the app's real module
resolution.

### Deviations
- **A factory, not a module-level singleton.** The first version imported
  `@/lib/env` at the top of `client.ts`, which made it impossible to exercise
  without mocking a module. Splitting the transport from its configuration is
  better design and is what made the verification above possible at all.
- **Verified through a temporary Next route handler.** Node's type stripping
  cannot resolve the `@/` alias or extensionless imports, and there is no web test
  runner until 12.1. The handler was deleted after the run; the script is recorded
  in this file's history.

### Known limitations
- No automated regression test — this was a one-off run. Task 12.1 should port
  these thirteen assertions into Vitest.
- No auth header or refresh handling; `credentials: "include"` anticipates the
  cookie session from phase 3.
- No retry logic. `isRetryable` exists so the query layer (1.8) can decide.
