# Task 1.11 — Internationalisation (English, Ukrainian)

## Objective

Every user-facing string translatable, with English and Ukrainian shipped and a
switcher — before phase 3 adds authentication screens that would otherwise have to
be retrofitted.

## Context

Added at the user's request; not in the original roadmap. Placed in phase 1
because it belongs with the frontend foundation, and sequenced before phase 3 on
purpose: sign-up, sign-in and password-reset screens are the largest block of
copy in the product, and translating them after the fact is strictly more work.

The API needs no message catalogue. Task 2.8 already returns a stable
machine-readable `code` with every failure; the client owns the wording, which is
also the only way the message can match the rest of the interface.

## Implementation steps

1. `next-intl` with locale-prefixed routing (`/en`, `/uk`) and a `[locale]`
   segment wrapping the existing route groups.
2. Middleware for negotiation: cookie first, then `Accept-Language`, then default.
3. Message catalogues for both locales; no string left in a component.
4. A switcher in both the app and dev headers that preserves the current path.
5. `<html lang>` follows the active locale.
6. Load the Cyrillic subset of Inter — the current build ships Latin only, so
   Ukrainian would fall back to a system font mid-page.
7. A check that the two catalogues have identical keys.

## Acceptance criteria

- `/en/workspace` and `/uk/workspace` both render, in their own language.
- `/` redirects to a negotiated locale; an unknown locale 404s.
- `Accept-Language: uk` gets Ukrainian on a first visit; the cookie wins after a
  switch.
- `<html lang>` matches the locale.
- Switching locale stays on the same page.
- The catalogues have the same keys, enforced by a check in `scripts/check.sh`.
- No user-facing literal left in a component.
- `scripts/check.sh` passes.

## Tests

12.1 owns the runner. Verified from served markup per locale, plus the catalogue
key check.

### Deviations
- **An unknown locale redirects before it 404s.** The spec said 404 directly;
  next-intl treats `/fr/...` as a path under the negotiated locale. The end state
  is a 404 either way, and the redirect is the friendlier of the two.
- **`ErrorState`, `Spinner` and `SubmitButton` lost their default copy.** A shared
  component with English baked into a default is a string no catalogue can reach.
  Callers now pass the text.
- **The `(dev)` gallery stays in English.** It is an internal reference surface;
  running it through the catalogue would fill the catalogue with strings no user
  ever sees. Its chrome — app name, "internal", the switcher — is translated.
- **`@parcel/watcher` and `@swc/core` install scripts denied** (ADR-006). They
  arrive with next-intl; the build was verified without them.
- **The contrast check's exemption path was stale** after the layout moved under
  `[locale]`, and the check caught it. The path is now a constant.

- **The docs drift check was too strict.** It required PROJECT_STATE's last
  completed task to be the *last ticked* roadmap entry, which broke as soon as
  completion order diverged from roadmap order — 1.11 was added and done after
  2.10. It now requires the named task to be ticked, which is the real invariant.

### Known limitations
- Ukrainian copy is my translation, not a native reviewer's. The catalogue is the
  one place to fix it.
- No pluralisation or date/number formatting in use yet; next-intl provides both
  when a screen needs them.
- The API's error codes have no catalogue entries yet (ADR-015) — the client
  currently shows the server's English fallback for a domain error.
