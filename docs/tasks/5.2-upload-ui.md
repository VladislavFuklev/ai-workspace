# Task 5.2 — Upload UI

## Objective

The way a person gets a document into a workspace: choose or drop files, see
what is happening, and understand any refusal.

## Ordering question

The roadmap puts the UI before the endpoint (5.3). A UI with nothing behind it
can only be verified by reading it, and this project's rule is that a check
nobody ran is not a check. Recommendation: build 5.3 first and keep the numbers
as they are, so 5.2 is exercised against a real endpoint. Decide before starting.

## Context

Storage exists (5.1) and enforces its own rules: 25 MB, an allowlist of four
content types, and a key the client cannot influence. The interface must refuse
the same things *before* the upload starts — a person should not wait for 25 MB
to travel before being told the file is too large — while never being the only
thing that refuses.

## Implementation steps

1. A drop zone that is also a real `<input type="file">`: drag-and-drop is an
   enhancement, not the only way in, and keyboard and screen-reader users need
   the input.
2. Client-side checks mirroring `ALLOWED_CONTENT_TYPES` and `MAX_OBJECT_BYTES`,
   named as a mirror in the code so the next person knows where the source is.
3. Per-file progress, and a queue when several are dropped at once.
4. Every failure state: too large, wrong type, network lost mid-upload, the API
   refusing, and the store being unavailable (503) — each with what to do next.
5. Cancel an upload in flight.
6. Messages in `en` and `uk`.

**Excluded:** the endpoint (5.3), document metadata and the list (5.4, 5.9),
extraction progress (5.6).

## Acceptance criteria

- The upload works with the keyboard alone, and the drop zone's state is
  announced rather than only coloured.
- A file the API would refuse is refused before it is sent, with the same words.
- An upload interrupted halfway leaves no half-document in the list.
- Cancelling stops the request, not just the spinner.
- Both catalogues have the same keys; `scripts/check.sh` passes.

## Tests

Against a running API. No browser automation until 12.8, so drag-and-drop
behaviour is verified by hand and the rest through the rendered markup.
