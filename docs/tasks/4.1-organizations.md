# Task 4.1 — Organizations

## Objective

The tenant boundary: the row every document, conversation and usage record will
eventually hang from.

## Context

Phase 3 gave us users. A user is a person; an organisation is who the data
belongs to. Getting this wrong is not a bug that shows up as a broken page — it
is one tenant reading another's documents, so the constraints go in first.

## Implementation steps

1. `organizations` table: name and a URL-safe slug, unique.
2. Slug generation from a name, with a validated format.
3. Repository and a create service.
4. Migration, reviewed by hand.

**Excluded:** membership (4.2), roles (4.3), endpoints (4.5 onwards).

## Acceptance criteria

- Two organisations cannot share a slug, enforced by the database.
- Slug uniqueness is case-insensitive.
- A generated slug is URL-safe for names with accents, punctuation and Cyrillic.
- A name collision produces distinct slugs.
- An empty or punctuation-only name is rejected.
- `scripts/check.sh` passes.

## Tests

Unit for slug generation; integration for the constraint.

| unit / integration | 165 / 70 pass |

### Deviations
- **Names are not unique, slugs are.** Two unrelated companies can both be Acme;
  refusing the second is a support ticket, not a safeguard. The address has to be
  unique because it identifies the tenant.
- **Cyrillic needs its own transliteration table.** `unicodedata` decomposition
  strips accents from Latin letters but leaves Cyrillic untouched, so a Ukrainian
  name would have produced an empty slug — an organisation with no address, in
  the language half the product ships in.
- **A random suffix, not a counter.** Counting needs a query per attempt and
  tells anyone reading a URL how many organisations share a name.
- **`slugify` returns empty rather than inventing a name.** A silently invented
  address is worse than a rejected input, and only the caller can ask for another.
- **Two Ruff exemptions, both scoped and explained.** `RUF001` flags Cyrillic that
  looks Latin — a homoglyph guard worth keeping. It is off for the
  transliteration table, which *is* that Cyrillic, and for tests, where Ukrainian
  data is the point.

### Known limitations
- No membership, so an organisation has no members and nothing can reach it —
  that is 4.2, and until then `create` is only callable from a service.
- Slugs cannot be changed; renaming an organisation keeps the old address.
- No per-tenant limits on how many organisations one user can create (10.6).
