# Task 0.7 — Documentation system

## Objective

Make the docs navigable and self-maintaining as the project grows past a handful
of tasks, without adding a docs toolchain.

## Context

`docs/` now holds five state documents plus a task file per task, and
`DECISIONS.md` is 13 ADRs in one file. It works, but nothing indexes it and
nothing checks it stays true. `scripts/ctx.sh` already summarizes state.

## Implementation steps

1. `docs/README.md` — an index: what each document is for and when to read it.
2. Decide whether to split `DECISIONS.md` into `docs/decisions/NNN-*.md` with an
   index, or keep one file. Record the choice.
3. A check that catches documentation drift: unticked roadmap entries with a
   completed task file, task files with no outcome section, dead relative links.
   Add it to `scripts/check.sh`.
4. Template for a task spec, so each one does not get reinvented.
5. Fold the ADR-format guidance out of `DECISIONS.md` into the template.

## Acceptance criteria

- A newcomer can tell from `docs/README.md` which file answers which question.
- The drift check fails on a broken relative link and on a roadmap entry that
  contradicts its task file; verified by introducing each.
- The check is part of `scripts/check.sh` and runs offline in under a second.
- No new dependency and no static-site generator.

## Documentation

Update `docs/ARCHITECTURE.md`, `PROJECT_STATE.md`, `CHANGELOG.md`, `ROADMAP.md`,
this file. An ADR only if the `DECISIONS.md` split is chosen.

### Deviations
- **The state check was a false negative at first.** `grep -q "0.6"` treats the dot
  as a wildcard and matched `026` inside the date `2026-09-12`, so a drifted
  PROJECT_STATE passed. Now it extracts both ids and compares them as strings.
  Found only because the failure case was actually exercised.
- **`_TEMPLATE.md` broke the check on its first run** — it contains an `## Outcome`
  heading. Files beginning with `_` are skipped.
- Split of `DECISIONS.md` considered and rejected (ADR-014).
